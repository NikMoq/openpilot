# Финальный план интеграции Camera Speed Control в SunnyPilot

**Проект:** SunnyPilot / Volkswagen PQ35 / штатный ACC 7N0
**Назначение:** автоматическое изменение уставки ACC перед камерами контроля скорости РФ посредством существующего ICBM.
**Базовый подход:** замена источника дорожных ограничений OpenStreetMap на локальную базу камер без создания дополнительного механизма эмуляции кнопок.

## 0. Обязательное исследование установленной версии

Перед разработкой Codex должен исследовать [https://github.com/NikMoq/openpilot/ICBM](https://github.com/NikMoq/openpilot/ICBM), и создать от него новую ветку с названием cam и всю работу продолжать только в ней.

Указанные ниже файлы и методы взяты из публичных исходников SunnyPilot. Они не являются гарантированными точками изменения в dev-c3.

Необходимо:

- Зафиксировать Git-коммиты SunnyPilot и opendbc.
- Установить фактическую цепочку формирования `vTarget`.
- Проверить действующие реализации ICBM и SLA.
- Выявить и сохранить локальные доработки PQ35, CAN и Panda.
- Не переносить код публичного `master` вслепую.

**Результат:** подтверждённая карта зависимостей и точек интеграции конкретной версии.

## 1. Диагностика всех источников ограничения скорости

**Точка входа — проверить:**

`openpilot/sunnypilot/selfdrive/controls/lib/longitudinal_planner.py`

В публичной версии `LongitudinalPlannerSP.update_targets()` выбирает минимальную целевую скорость из четырёх источников:

| Источник           | Назначение                                       |
| ------------------ | ------------------------------------------------ |
| `cruise`           | Базовая программная уставка                      |
| `sccVision`        | Ограничение скорости на поворотах по видеомодели |
| `sccMap`           | Ограничение скорости на поворотах по карте       |
| `speedLimitAssist` | Ограничение скорости по дорожным данным          |

До разработки CameraSpeedSource добавить диагностику:

- Текущий выбранный `longitudinalPlanSource`.
- Все четыре исходные целевые скорости.
- Итоговый `longitudinalPlanSP.vTarget`.
- `carState.vCruise` и `carState.vCruiseCluster`.
- `cruiseState.speedCluster` штатного ACC.
- Состояния SLA и ICBM.
- Сформированную команду `increase`, `decrease` или `none`.

**Цель:** определить, почему ICBM иногда самостоятельно снижает уставку даже после отключения SCC-V. Исключить конфликт неизвестного источника скорости с будущим CameraSpeedSource.

## 2. Локальная база камер Российской Федерации

Создать независимый модуль `CameraSpeedSource`.

Источник данных — [https://speedcamonline.ru/cg77/Rus/comment/](https://speedcamonline.ru/cg77/Rus/comment/), ориентировочно 75 000+ записей; фактический состав и достоверность базы проверить отдельно.

Обязательные данные камеры:

- Уникальный идентификатор.
- Географические координаты.
- Направление контроля.
- Тип камеры.
- Ограничение скорости, если известно.
- Идентификатор дороги или дополнительные данные привязки, если доступны.

Модуль должен использовать GPS и направление движения для обнаружения камер впереди автомобиля.

Основные правила:

- Встречные камеры не вызывают снижение скорости.
- Камеры параллельных дорог и развязок не должны определяться только по близости координат.
- Камеры без достоверного ограничения скорости не формируют команду.
- Повторные GPS-измерения не должны активировать одну камеру многократно.
- Работа с базой осуществляется локально, без обязательного интернет-соединения.

## 3. Расстояние реагирования на камеру

Добавить в настройки SunnyPilot круиз в меню где раньше были данные скорости от osm:

**Camera Speed Control** — включение и отключение функции.

**Camera Reaction Distance** — настройка расстояния начала реагирования:

50–1000 метров, например с шагом 50 метров.

Пример: водитель выставил 300 метров. При достижении этой дистанции CameraSpeedSource активирует ограничение соответствующей камеры.

Важно: выбранное расстояние означает начало реагирования, а не гарантию достижения нужной скорости точно перед камерой. Реальный результат зависит от скорости автомобиля, работы ACC и ICBM. Не создавать отдельный агрессивный алгоритм торможения.

## 4. Замена ограничений OSM

**Основная точка входа — проверить:**

`openpilot/sunnypilot/selfdrive/controls/lib/speed_limit/speed_limit_resolver.py`

Методы-ориентиры:

- `_get_from_map_data()`
- `_process_map_data()`
- `_calculate_map_data_limits()`
- `_resolve_limit_sources()`

Вместо получения ограничений скорости из OSM использовать совместимые данные CameraSpeedSource.

Сохранить существующую семантику полей:

| Поле                      | Назначение                             |
| ------------------------- | -------------------------------------- |
| `speedLimit`              | Ограничение камеры, м/с                |
| `speedLimitValid`         | Достоверность текущего ограничения     |
| `speedLimitAhead`         | Предстоящее ограничение                |
| `speedLimitAheadValid`    | Достоверность предстоящего ограничения |
| `speedLimitAheadDistance` | Расстояние до объекта                  |

Точную схему сообщений и их использование проверить по локальной версии.

**Принцип:** подменить только данные дорожных ограничений. Не отключать GPS, отображение дороги, навигацию и SCC-M.

Предпочтительно выполнять подмену внутри адаптера SpeedLimitResolver, а не глобально переписывать `liveMapDataSP`, которым пользуются другие подсистемы.

OSM не должен самостоятельно ограничивать скорость в режиме Camera Speed Control.

## 5. Сохранение штатной прибавки к ограничению

Сохранить существующий механизм:

`SpeedLimitOffsetType`
`SpeedLimitValueOffset`

Пример:

- Камера — 60 км/ч.
- Штатная прибавка — +15 км/ч.
- Расчётная цель — 75 км/ч.

Не создавать вторую систему применения прибавки. Избежать повторного сложения.

Штатный SpeedLimitResolver должен рассчитывать конечное ограничение и передавать его в LongitudinalPlannerSP.

## 6. Автоматическое подтверждение ограничений камер

**Точка входа — проверить:**

`openpilot/sunnypilot/selfdrive/controls/lib/speed_limit/speed_limit_assist.py`

Методы-ориентиры:

- `update_state_machine_non_pcm_long()`
- `_update_non_pcm_long_confirmed_state()`
- `apply_confirm_speed_threshold`
- `get_v_target_from_control()`

В публичной реализации SLA существует `preActive`, в котором ожидается подтверждение водителя кнопкой `SET−` или `decelCruise`.

Для CameraSpeedSource реализовать **автоматическое принятие достоверного ограничения новой камеры** без обязательного нажатия кнопки.

При этом:

- Сохранить проверки включённого ACC и доступности управления.
- Не менять глобально правила подтверждения обычных ограничений OSM.
- Не имитировать фиктивное нажатие кнопки водителя.
- Не изменять механизм формирования CAN.
- Не активировать ограничение, если GPS или привязка камеры недостаточно достоверны.

Для камер допускается автоматический переход в `active` через существующую машину состояний.

Отдельный режим ожидания подтверждения до 20 секунд, обсуждавшийся ранее, можно оставить как необязательную настройку ручного SLA. Для автоматического режима камер он не требуется.

## 7. Сохранение скорости водителя и ручной приоритет

Добавить отдельное состояние `driverSetSpeed`.

Оно должно хранить именно установленную водителем целевую скорость, а не временную уставку, сформированную ICBM.

**Пример:**

1. Водитель установил ACC на 100 км/ч.
2. Обнаружена камера 60 км/ч.
3. Прибавка +15 формирует цель 75 км/ч.
4. ICBM снижает уставку ACC до 75.
5. `driverSetSpeed` продолжает хранить 100.
6. Камера пройдена.
7. Цель возвращается к 100, если другие штатные источники не требуют меньшей скорости.

Если водитель изменил скорость кнопками во время действия камеры, новое ручное значение необходимо учитывать отдельно.

**Ручное вмешательство имеет приоритет.** Если водитель повысил уставку вопреки ограничению камеры, автоматическое ограничение именно этой камеры больше не навязывается до окончания её зоны.

При появлении следующей камеры начинается новый независимый цикл.

Отдельно проверить, не отражаются ли команды, сгенерированные ICBM, в `CarState.buttonEvents` как обычные нажатия. Система не должна ошибочно принимать собственные команды за действия водителя.

## 8. Завершение зоны камеры и восстановление скорости

После подтверждённого проезда камеры:

- Завершить её активную зону.
- Снять временное ограничение.
- Исключить повторное срабатывание той же камеры из-за колебаний GPS.
- Восстановить сохранённую водительскую цель с учётом остальных ограничителей планировщика.
- Не применять прибавку +15 к сохранённой скорости водителя.

**Принципиально:** камера не считается источником постоянного дорожного ограничения после проезда.

За пределами зоны камер целевая скорость определяется водителем и другими разрешёнными контроллерами SunnyPilot.

Проверить обработку кэшированных значений в SpeedLimitResolver:

- `speed_limit_last`
- `speed_limit_final_last`
- `speed_limit_last_valid`

Не допустить сохранения ограничения пройденной камеры как действующего.

При потере GPS внутри активной зоны не выполнять неожиданное увеличение скорости: восстановление водительской уставки возможно после достоверного определения окончания зоны либо решения водителя.

## 9. Разделение состояний камер

CameraSpeedSource должен различать следующие состояния:

| Состояние         | Значение                                                  |
| ----------------- | --------------------------------------------------------- |
| `IDLE`            | Подходящих камер впереди нет                              |
| `APPROACHING`     | Камера обнаружена, но зона реагирования ещё не достигнута |
| `ACTIVE`          | Ограничение камеры передаётся в SLA                       |
| `DRIVER_OVERRIDE` | Водитель отменил ограничение текущей камеры               |
| `PASSED`          | Камера пройдена, временный лимит снят                     |

Важный момент: две последовательные камеры с одинаковым ограничением должны распознаваться как два независимых события, по их ID, а не только по изменению числового значения скорости.

## 11. UI и диагностика

В существующем разделе Cruise / ICBM добавить:

- Переключатель **Camera Speed Control**.
- Выбор расстояния реагирования 50–1000 м.
- Использование существующей настройки прибавки.
- Индикацию обнаруженной камеры, её ограничения и расстояния до неё.
- Индикацию ручного переопределения камеры.

Для диагностики предусмотреть запись выбранного источника скорости, всех кандидатов `vTarget`, ID активной камеры, состояний SLA/ICBM, водительской и штатной уставок ACC.

Пути UI в публичном проекте:

- `openpilot/selfdrive/ui/sunnypilot/layouts/settings/cruise.py`
- `openpilot/selfdrive/ui/sunnypilot/layouts/settings/cruise_sub_layouts/speed_limit_settings.py`

**Перед редактированием проверить структуру интерфейса именно в dev-c3.**

## Критерии завершения

Функция считается реализованной, когда:

1. ICBM самостоятельно снижает уставку ACC перед достоверно обнаруженной камерой без подтверждения водителем.
2. Используется существующая прибавка к ограничению скорости.
3. Водитель может вручную изменить скорость; текущая камера больше не навязывает своё ограничение.
4. После проезда камеры восстанавливается водительская уставка, если другие штатные контроллеры не требуют меньшей скорости.
5. OSM не вмешивается в управление дорожными ограничениями в режиме Camera Speed Control.
6. Работа SCC-V, SCC-M и других существующих компонентов не нарушена.
7. Код Volkswagen и Panda остаётся совместимым с текущей отлаженной реализацией.
8. Все изменения и точки интеграции проверены именно на установленной версии SunnyPilot.

**Основной архитектурный принцип: изменяем источник данных и управление жизненным циклом ограничения, не создавая второй контроллер круиз-контроля поверх ICBM.**
