# Локальная статистика поездок

Обе карточки (`DriveStats` на главном экране и в разделе «Поездки») читают
`/data/trip_stats/stats.json`. Запросов к comma, DongleId, облачного кеша и
ожидания ответа сервера в этом виджете больше нет. Остальные сетевые функции
устройства это изменение не затрагивает.

Нет файла/валидных данных — отображается «—». Последняя корректная локальная
сводка сохраняется в памяти при временной ошибке чтения. Короткие расстояния
и часы показываются с десятыми; русский язык использует десятичную запятую.
Известное неполное число исторических поездок отображается «—» или «≥N»;
папки с диагностическими записями не превращаются в вымышленные поездки.

Производитель и формат описаны в `system/TRIP_STATS.md`. Новых Params-ключей нет.
Для интеграции координатору необходимо добавить в список managed processes:

```python
PythonProcess("tripstatsd", "system.tripstatsd", always_run),
```

Процесс должен работать и на стоянке: это сохраняет итог поездки и обновляет
скользящие семь календарных дат UTC. Перезапуск интерфейса его не останавливает.
При резком отключении питания может потеряться последний несохранённый отрезок
(обычно до 30 секунд); уже сохранённые измерения не обнуляются.

## Проверки без устройства

```sh
python3 system/tests/test_trip_stats.py
python3 tools/trip_stats/test_recover.py
c++ -std=c++17 -fPIC -I. tools/trip_stats/test_display.cc \
  $(pkg-config --cflags --libs Qt5Core) -o /tmp/trip-display-test
/tmp/trip-display-test
```

На Linux выполняются также проверки файловой блокировки, атомарной записи и
отказа записи. Windows пропускает три POSIX-проверки.

Снимки настоящего Qt5-виджета: после обычной host-сборки `--ru-preview`:

```sh
python3 tools/trip_stats/build_preview.py
cd selfdrive/ui
PARAMS_ROOT="/tmp/trip-stats-params-$(date +%s)-$$" \
TRIP_STATS_ROOT="/tmp/trip-stats-data-$(date +%s)-$$" QT_QPA_PLATFORM=xcb \
  xvfb-run -a -s "-screen 0 2200x1120x24" \
  ../../.native-build/pc/trip-stats-preview /tmp/trip-stats-images
```

Стенд отказывается использовать существующий `PARAMS_ROOT` или пути вне
тестового префикса `/tmp/trip-stats-`. Семь случаев: километры, мили, короткая
поездка, отсутствие данных, ширина раздела настроек, большие числа и неполное
восстановление истории. Он не отправляет сообщения автомобилю и не подтверждает
действия в интерфейсе.

## Восстановление

`recover.py` принимает явно указанные локальные rlog/qlog/диагностические записи
и создаёт новый JSONL с измеренными отсчётами и контрольными суммами источников.
Он не обращается к устройству/сети и не записывает рабочую статистику.

```sh
python3 tools/trip_stats/recover.py /path/to/recording --output /tmp/measured.jsonl
```

Перед импортом нужно проверить происхождение и отсутствие пересечения с уже
учтёнными живыми поездками. Повтор идентичного источника не удваивает пробег;
неизвестная история не оценивается по числу файлов, длительности владения или
показаниям другого источника. Системные метрики `/data/stats*` требуют отдельной
проверки состава и сами по себе не являются журналом пробега.
