# Русская локализация Qt-интерфейса

Пакет предназначен для Comma 3 / Mr. One, Qt 5.12.8, ветка `dev`.
База исходников: `6395399fc448c46a8d265be6cdd9e82d3597a8a9`.
Статус подготовки: **OFFLINE_BUILD_AND_QT_CHECKS_PASS**. После публикации в `dev`
пользователю ещё предстоит проверить обновление на своём устройстве.

## Состав и проверочный охват

- Каталог `selfdrive/ui/translations/main_ru.ts`: 1293 сообщения, 106 контекстов.
  Сохранены 778 исходных идентичностей; добавлены 515 ключей. Пять сообщений
  имеют по три русские формы. В последнем полном Qt5 `lupdate` — 788 ключей,
  пропущенных ключей нет. Динамические тексты проверяются дополнительно.
- 19 учебных страниц: русский текст накладывается на исходные изображения;
  иллюстрации, области нажатия и значения согласия остаются прежними.
- Предупреждения: проверочный набор содержит 249 случаев. Переводится только
  представление текста; события, приоритеты и звуки не меняются.
- Ошибки камер: 38 собственных постоянных сообщений и пять динамических
  шаблонов. Коды, числовые значения и неизвестные внешние диагностики сохраняются.
- Русский справочный HTML выбирается по языку; исходный английский ресурс сохранён.
- Проверочная серия интерфейса включает 144 снимка в 37 профилях настоящих Qt-виджетов
  с глубокими меню, раскрытыми описаниями и прокруткой, а также 12 диалогов.
  Количество снимков само по себе не означает успешную проверку всех состояний:
  итоговые отчёты и снимки должны соответствовать точным хешам UI и QM поставки.

Рендер выполняется настоящим Qt 5.12.8 с исходными шрифтами, а не макетом HTML.
Сценарии Qt на хосте, сборка ARM64 и работа устройства — отдельные подтверждения.
Последний перевод использует «Стоянка» для режима Offroad, «Управление круизом
(ICBM)» и «Нештрафуемый лимит» для добавки к ограничению у камеры.
Подсказки круиза раскрываются нажатием заголовка независимо от переключателя.

## Сборка в Docker

Команды выполняются из корня этой копии исходников на Linux/в Linux-контейнере.
Используйте отдельный образ и отдельный каталог результатов для этой сборки.
Сборщик создаёт `.native-build/pc` и `.native-build/device`; он не устанавливает
результат на устройство.

```sh
docker build --platform linux/amd64 -t pq35-ui-ru-build \
  -f tools/ui_build/Dockerfile .
docker run --rm -v "$PWD:/work" pq35-ui-ru-build -j2
docker run --rm -v "$PWD:/work" pq35-ui-ru-build --ru-preview -j2
```

Для ARM64 необходим полный подготовленный sysroot с целевыми Qt 5.12.8,
заголовками и библиотеками времени выполнения, а также соответствующие целевые
EGL/GLES/vendor-библиотеки. Пустого `/opt/sysroot` из образа недостаточно:
сборщик проверяет зависимости и останавливается при неполном комплекте.
`ARM_SYSROOT` и `DEVICE_VENDOR_LIBS` ниже — локальные каталоги этих материалов,
а не адреса устройства. Копия sysroot должна допускать исправление абсолютных
символических ссылок сборщиком; оригинальные материалы сохраняются отдельно.

```sh
docker run --rm -v "$PWD:/work" \
  -v "$ARM_SYSROOT:/arm-sysroot" \
  -v "$DEVICE_VENDOR_LIBS:/vendor-libs:ro" \
  pq35-ui-ru-build --device --sysroot /arm-sysroot \
  --vendor-libs /vendor-libs -j2
```

Результаты: `.native-build/device/ui`, `.native-build/device/resources/main_ru.qm`
и `.native-build/device/manifest.json`. До формирования поставки сверяются
архитектура, динамические зависимости, совместимость целевых библиотек и хеши.
Финальные `selfdrive/ui/ui` и QM формируются координатором из проверенной сборки;
эти команды не выполняют установку, коммит или публикацию.

## Повторяемые проверки

```sh
python3 tools/ui_build/test_russian_presentation.py
```

Тест использует отслеживаемый `russian_presentation_baseline.json`, закреплённый
на базе `6395399`. Он работает без `.git`, поэтому остаётся содержательным после
коммита и в архиве исходников. Проверяются нормализованные критические файлы,
порядок записей параметров, сигналов, вызовов доступности и вычислений; новые
модули представления не должны записывать параметры управления.

После сборки QM отдельно запускается нативный тест ошибок камер:

```sh
c++ -std=c++17 -fPIC -I. tools/ui_build/camera_error_test.cc \
  $(pkg-config --cflags --libs Qt5Core) -o /tmp/camera-error-test
/tmp/camera-error-test .native-build/pc/resources/main_ru.qm \
  selfdrive/ui/translations/main_ru.ts
```

Ожидаемые маркеры: `CAMERA_ERROR_STATIC_CONTEXT_COUNT=38 DYNAMIC_TEMPLATE_COUNT=5`
и `CAMERA_ERROR_PRESENTATION_TEST_PASS`. Проверка повторно пройдена на финальном QM с 1293 сообщениями.

Русские настройки снимаются только с новым изолированным `PARAMS_ROOT`:

```sh
cd selfdrive/ui
PARAMS_ROOT="/tmp/ru-ui-preview-$(date +%s)-$$" \
  QT_QPA_PLATFORM=xcb xvfb-run -a -s "-screen 0 2200x1120x24" ../../.native-build/pc/ru-preview /tmp/ru-ui-preview-images
```

Программа отказывается использовать существующее дерево параметров.
Итоговый JSON включает состояние заголовков/подсказок, параметры, прокрутку,
метрики подписей и сведения о снимках. Диалоговый стенд показывает и скрывает
конструкторы без подтверждения действий; стенд предупреждений использует
синтетические тексты. Они не требуют CAN, поездки или изменения управления.

## Диагностика QA и проверка устройства

Встроенный модуль `comma_ui_qa` по умолчанию выключен. Установка обработчиков
диагностики требует явного opt-in `COMMA_UI_QA_CAPTURE=1`; обычный запуск UI
не включает захват или тестовую навигацию. Диагностика используется отдельно
для согласованной проверки интерфейса, с проверкой состояния стоянки и
ограниченными именованными действиями. Она не является алгоритмом автомобиля.

После публикации `dev` требуется проверка пользователем на конкретном устройстве:
загрузка русского языка, реальные шрифты и размеры дисплея, глубокие меню,
прокрутка, раздельное нажатие заголовка/переключателя, скрытие подсказок при
выходе и гашении экрана, обучение и предупреждения. Хостовые снимки и успешная
компиляция не заменяют это подтверждение. EPS/Panda и настройки управления
не входят в пакет локализации.
